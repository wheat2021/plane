# 环境配置（Environments）

> 原文: https://docs.warp.dev/agent-platform/cloud-agents/environments

Environment 确保你的 Cloud Agent 在所有触发器下使用一致的工具链运行。

## 核心特性

- **跨触发器一致行为**：从 Slack 触发的工作流与从 Linear 或 CLI 触发的行为完全一致
- **一次配置，多处复用**：定义一次 Docker 镜像和设置，然后在不同触发器和宿主机上复用
- **运行全透明**：可检查每次运行使用的镜像、仓库和命令，方便调试失败或重现结果

---

## 关于 Environment

Environment 定义代理**如何运行**，而非**做什么**。它是 Oz 平台自动化（Cloud Agent、集成、API 运行）所必需的，但交互式本地使用不需要。

### 典型组成

- **Docker 镜像（必填）**：代理运行的工具链和运行时
- **仓库/工作区**：一个或多个代理可克隆和操作的仓库
- **启动命令**：准备工作区的命令（如依赖安装、构建、引导）

### 运行时设置

- **环境变量**：在 Dockerfile 中用 `ENV` 指令配置，或在运行容器时传入
- **密钥**：对于凭证和敏感数据，使用 [Agent Secrets](./06-secrets.md)，它们在运行时安全注入

### Environment 不是什么

- **宿主机（Host）**：决定执行发生在哪里（Warp 托管 vs 自托管）
- **Agent Profile**：控制代理行为（权限、模型选择、默认值），不是运行时环境
- **Rules**：决定代理的响应和决策，不定义容器或工具链
- **MCP**：连接代理到外部工具和数据
- **单次运行上下文**：触发器特定数据（Slack 线程、PR 元数据、CI 日志）附加到单个任务，不属于环境配置

---

## 在 Oz 平台中的位置

执行流程中的组件：

1. **触发器** → 事件启动工作
2. **任务** → Warp 创建被追踪的任务
3. **环境** → 任务使用环境定义执行上下文
4. **宿主机** → 环境在宿主机上运行（Warp 托管或自托管）
5. **代理执行** → 工作流在准备好的环境中运行
6. **输出** → 运行产出 PR、消息、报告或会话记录

> 本地代理运行（使用 `oz agent run`）**不需要环境**，直接使用当前机器的设置。

### 宿主机与环境

环境定义**如何**运行，宿主机决定**在哪里**执行：

- **Warp 托管（默认）**：Warp 提供基础设施，适合大多数用户
- **自托管**：你提供基础设施（在你的云或网络中的 runner），适合合规需求
- **本地（即将推出）**：在本地机器上运行环境，用于沙箱开发和测试

同一环境可在不同宿主机上以相同行为运行。

## 运行时流程

当你触发代理时，Warp 按以下流程执行：

1. **Warp 接收触发**：捕获消息内容和任何关联上下文
2. **创建执行环境**：从环境定义的 Docker 镜像启动隔离的执行上下文
3. **克隆仓库**：将关联的 GitHub 仓库克隆到容器中
4. **运行启动命令**：执行配置的设置命令（安装依赖、运行构建等）
5. **代理工作流运行**：代理使用提供的上下文、工具和权限执行任务
6. **结果回传**：进度更新、摘要和结果回传到触发源（Slack、Linear 等），或在任务记录中可用
7. **容器销毁**：完成后容器被拆除。每次运行从干净、隔离的环境开始

---

## 何时使用

**推荐使用的场景：**

- **集成和定时任务**：运行从 Slack、Linear、GitHub Actions、定时或其他集成启动，需要每次一致的行为
- **CI 和远程自动化**：宿主机不一致时（如不同 runner、不同基础镜像）
- **团队标准化**：希望所有人的自动化运行使用相同的镜像、仓库和设置步骤
- **特定工具链工作流**：工作流依赖特定语言版本、linter、构建工具或系统包

**可以跳过的场景：**

- 交互式本地运行，已在工作目录中且依赖现有机器设置

### 决策清单

以下任一条件成立时选择使用 Environment：

- 运行必须跨触发器/宿主机保持一致
- 工具链必须固定（已知镜像 + 确定性设置步骤）
- 工作流在团队间共享，多人或系统会运行并期望可重现的结果

---

## 配置环境

可通过 Warp 引导式设置或 CLI 创建和配置环境。

### 前置条件

- 一个或多个代理应克隆和工作的 GitHub 仓库
- 一个可公开访问的 Docker 镜像（如 `node`、`python`、`rust`）

> **重要**：不支持基于 musl 的 Docker 镜像（如 Alpine Linux）。Warp 代理运行时需要 glibc。请使用基于 glibc 的镜像（如 Debian、Ubuntu 或 Docker Hub 官方镜像的默认非 Alpine 变体）。

> **建议**：每个代码库创建一个环境，然后在 Slack、Linear 和 CLI 运行等触发器间复用。
